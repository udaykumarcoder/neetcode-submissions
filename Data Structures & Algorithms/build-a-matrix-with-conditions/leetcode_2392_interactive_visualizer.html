Algorithm Breakdown & Complexity Analysis

1. Decoupling 2D into Two 1D Orders

Row constraints (above → below) only restrict vertical indices, while column constraints (left → right) only restrict horizontal indices. Because each number 1..k appears once in the matrix, solving two independent topological sorts gives a unique coordinate (val_to_row[num], val_to_col[num]) for every number without collisions.

2. Cycle Detection: path vs visit

visit tracks all nodes ever explored so we never re-compute a finished subgraph. path tracks only ancestors on the current DFS recursion stack. If src in path, we found a back-edge (a cycle like 1 → 2 → 1), making a valid ordering impossible (returns []). Post-order appends src after all descendants finish, so reversing order[::-1] yields the topological sort.

3. Time & Space Complexity

  • Time Complexity: O(k² + R + C) — Building graphs and running DFS takes O(k + R + C), and initializing/filling the k × k matrix takes O(k²).
  • Space Complexity: O(k² + R + C) — Adjacency lists store R + C edges, recursion stack & sets use O(k), and the output matrix uses O(k²).
